# Мотивация

Без системы трейсинга сложно разобраться в истинных причинах происходящего, и если мы будем действовать слепо, велика вероятность принятия неверных решений, например того что придется переписать техническое решение полностью, в частности MES, купленную, стоит заметить с исходниками как раз в том числе и по той причине что руководство решило что разработка своей MES это дорого, и не является целью данного бизнеса. Следовательно, нам важно понимать причинно следственные связи возникающих проблем, прежде чем что то делать, более того, ценно было бы прогнозировать их. Здесь нам и поможет трассировка совместно с мониторингом.

Трэйсинг также поможет в случае возникновения инцедентов, разобраться в причинах, и исправить ситуацию.

Трейсинг следует добавить в следующие сервисы:

1. Internet Shop
2. Shop API
3. CRM
4. CRM API
5. MES 
6. MES API

Следуте сделать акцент на следующих метриках: 

Бизнес метрики:

1. Время расчета стоимости изделия 
2. Количество потеряных заказов
3. Время нахождения заказов в каждом из статусов

Технические метрики: 

1. Наличие и количество ошибок в работе сервисов
2. Количество попыток retry и частота запросов
3. Время выполнения операций 

## Цели внедрения трассировки

1. Выявление проблем и увеличение скорости их устранение, помощь в разборе инцедентов, ведь нам будут доступные исторические данные о работе системы, а также поток текущих 
2. Экономия средств на разработку, ведь мы не будем делать того что не требуется, оптимизировать там где и так все хорошо
3. Оптимизация в работе системы на основании полученных данных будет происходить более эффективно, а главное мы сможем видеть результаты и делать выводы

# Предлагаемое решение

1. Внедрить OpenTelemetry как основной инструменты для распределенной трассировки и сбора метрик 
   1.1 Поднять OpenTelemetry Collector - ключевой компонент экосистемы OpenTelemetry, представляющий собой централизованный механизм для получения, обработки и экспорта телеметрических данных из приложений.
   1.2 Реализовать функционал OpenTelemetry API/SDK в наших сервисах - используем для сбора метрик
2. Поднимаем Prometheus-server для хранения метрик ( + Alertmanager )
3. Поднимаем Grafana для просмотра метрик 
4. Мы также поднимем Jaeger для отображения распределенной трассировки
5. Настраиваем дашборды в Grafana
6. Настраиваем Alertmanager

Какие данные нас интересуют:

    1. Наименование сервиса и сервера
    2. Дата и Время
    3. Вызовы сервисов (протокол, эндпойнт, параметры запроса, код ответа, тело ответа, время выполнения)
    4. Изменения статусов и все что касается "движения" заказа (идентификатор заказа, статус заказа, наименование операции)
    5. Время выполнения операции

# Компромиссы

Нам не обязательно в самом начале мониторить всю систему целиком, достаточно выбрать наиболее критичный на наш взгляд путь, например: 

1. Shop API
2. MES API

Возможно + CRM API (ну или следующим этапом)

# Аспекты безопасности

1. В трейсинг недолжны попасть приватные данные (ФИО, email, ...) для этого следует выделить объекты безопасности
2. Желательно закрыть всю ситему VPN
3. Все соединения с клиентами должны осуществляться по защищенным протоколам типа TLS/SSL
4. Обязательна процедура аутентификации\авторизации (система должна работать только с пользователями которых знает)

Как итог - система трэйсинга, это потенциальная точка для утечки ценных, приватных данных, мы должны контролировать и предоставлять доступ только для доверенных пользователей, при этом максимально изолировать всю систему от остальных, при этом, мы должны понимать, кто и когда получал доступ. Остальные пользователи не должны иметь доступ к трэсингу, и в целом получать доступ к системе по защищенным каналам.

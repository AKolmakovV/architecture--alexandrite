# Мотивация

Внедрение кэширования это проверенный и относительно не дорогой и быстрый способ улучшить производительность системы в целом, или отдельных ее частей. Хочется упомянуть что само по себе кэширование не решает проблему, но в значительной мере позволяет:

1. Увеличить производительность системы
2. Снизить нагрузку на сервисы

В нашем случае стоит обратить внимание не следующие операции и сервисы:

1. Расчёте стоимости производства изделия
2. Медленная загрузка первой страницы MES
3. MES API нагруженый сервис, мы можем внедрить кэш для хранения активных заказов, это также увеличит скорость работы MES

# Предлагаемое решение

Мы внедрим кэширование для следующих сервисов.

1. MES
2. MES API
3. Во все WEB приложения, для статических ресурсов.

Также мы следуем негласному правилу - кэш нужно располагать как можно ближе к клиенту.

## MES

1. Применяем паттерн Cache-Aside
2. Реализуем на базе Redis
3. Основная цель для кэширования - дашборды, их конфигурация, информация о пользователях
4. Мотивация: Частично решим бизнес проблему с медленной загрузкой MES 

Описание Cache-Aside: 

Принцип работы:

   * Сначала система ищет данные в кэше
   * Если данные не найдены, происходит запрос к MES API
   * Полученные данные загружаются в кэш
   * Данные отдаются запрашивающим клиентам

Основные преимущества:

   * Повышение производительности системы
   * Простота реализации
   * Снижение нагрузки на MES API

Плюс Cache-Aside также в том что "модель данных в кеше может отличаться от модели данных в БД/API" MES это Frontend, следовательно модель данных используемая в MES действительно может отличаться от модели данных в MES API. Также Cache-Aside быстро вернет данные так как большинство данных редко меняются (дашборды, их конфигурация). 


## MES API

Сервис высоконагруженный, помимо внутренних пользователей, к нам присоединились внешние через MES API, требуется снизить нагрузку на сервис при этом гарантировать пользователю запись данных либо вернуть ошибку.

1. Применяем паттерн Write-Through
2. Реализуем на базе Redis
3. Основная цель для кэширования - заказы
4. Мотивация: MES API стало доступно множеству пользователей

Описание Write-Through: 


Принцип работы:

   * При записи данных приложение сначала записывает их в кэш
   * Система кэширования синхронно обновляет данные в основной базе данных
   * Операция записи считается завершенной только после успешного обновления обоих хранилищ

Особенности чтения данных:

   * Сначала система ищет данные в кэше
   * Если данные есть - возвращает их из кэша
   * Если данных нет - извлекает их из базы данных, сохраняет в кэше и возвращает приложению

Преимущества:

   * Гарантирует актуальность данных в кэше и базе
   * Предотвращает работу со “старыми” версиями данных
   * Обеспечивает быстрое чтение благодаря постоянному обновлению кэша
   * Минимизирует риск потери данных при сбоях системы

Для нас крайне важно гарантировать целостность данных, и минимизировать риски потери данных. Скорость также очень важна.

## Стратегия инвалидации кеша

Временная инвалидация - выбор для MES, для тех данных что выбраны в целе достаточно будет периодически их обновлять. 
Программная инвалидация - выбор для MES API, нам потребуется сложная логика отслеживания изменений заказа, которые могут происходить со стороны CRM 


Вероятно кэширование потребуется также и для CRM API его реализация будет аналогична MES API, как и цели для кэширования, способ инвалидации. Данное решение, на основе одного из описаний системы - "заказ создаётся в CRM через получение сообщения из очереди от MES" т.е. заказ создается CRM, и нагрузка на MES вызывает нагрузку на CRM. Программная инвалидация опять же, по причине того что статус заказа может меняться в разных местах.
